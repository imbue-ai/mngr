mngr_azure: the Azure provider now registers its backend lazily, so a plain `mngr` invocation (config / list / help / version) no longer imports the heavy Azure management SDK. The setuptools entry point moved from `imbue.mngr_azure.backend` to a new thin `imbue.mngr_azure.plugin` module that carries only lightweight metadata (backend name, config class, build/start help text) and defers importing the backend implementation -- and its `azure.mgmt.compute` / `azure.mgmt.network` / `azure.mgmt.resource` clients -- until an Azure provider is actually operated. The `mngr azure ...` operator command group is likewise loaded on demand via a lazy CLI group. This cuts `mngr` CLI cold-start latency (Linear MIND-179); there is no change to Azure provider behavior.
