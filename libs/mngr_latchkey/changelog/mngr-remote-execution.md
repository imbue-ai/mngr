- The `permission-requests` gateway extension accepts a sixth request type, `remote-execution`, whose payload is empty and whose effect is one `remote-execution-<device id>` permission under `latchkey-self`, pinned by a `const` path to the approving desktop's own `POST /minds-api-proxy/api/v1/remote-execution/<device id>` route, so a desktop can never grant commands on another and nothing under a wider prefix matches. It takes no approve override. A new `remote_execution` module reads and writes the grant's name; the name carries no product prefix.
