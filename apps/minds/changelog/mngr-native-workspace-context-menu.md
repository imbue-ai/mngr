On macOS, right-clicking in the desktop app, inside a workspace included, now opens one native menu that combines the macOS items with the workspace's own. It offers spelling suggestions and Add to Dictionary, Look Up, Cut / Copy / Paste / Select All, Copy Link, Copy Image and Copy Image Address, Share, Speech, Services, and, in dev builds, Inspect Element. Around those sit the workspace page's own rows (actions, check rows, and submenus) and its Copy reference / Explain... / Modify... rows, with SF Symbol icons. Before, a right-click inside a workspace showed only the workspace's HTML menu, with none of the macOS items. A page that handles a right-click itself (the Screen app's remote desktop, a press that closes an open menu) still gets its own.

The chrome tells the workspace it draws the menu with the new optional `drawsContextMenus` field on `minds:embedder-capabilities` (embed contract v16), on macOS only. On Linux, workspace pages keep their own menu, and pages without one (the terminal) now get the native Cut / Copy / Paste menu. On each right-click, main reads the clicked frame's rows through the page's `__studioContextMenu` bridge (its name, sections, row kinds, and bounds pinned for both repos by `electron/page-menu-bridge.json`), treating them as untrusted, and runs a picked row back in that frame. A frame that offers no rows, or does not answer within 300 ms, gets the native items alone.
