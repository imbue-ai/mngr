The workspace profile contract fixture (`workspace_profile_contract.json`) gains four per-platform chord lists the template's keyboard shortcuts screen mirrors: `refused_chords` (Ctrl+Alt+Del, which no binding may claim on any platform), `browser_reserved_chords` (what a browser keeps from its pages, hidden when the workspace runs in one), `os_kept_chords` (what an OS keeps from every app, warned about), and `host_acted_chords` (Alt+F4 and Alt+Space on Windows, which the desktop app intercepts for a binding to win). The account-settings write path refuses a refused chord as it refuses an off-grammar one.

`electron/dev/key-probe.js` is a bare Electron window (and `key-probe.html` a page for any browser) that logs every keystroke the main process and the page see, for pinning those lists from what actually arrives on each OS and browser.

The desktop app runs a workspace's shortcuts before any page or the OS sees the key. A workspace reports its workspace-wide shortcuts and every app's (`minds:shell-shortcuts`, embed contract v15); main then runs a workspace-wide one in the workspace wherever focus is, the terminal, the Screen and a pulled-out window included (`minds:run-shortcut`), and takes Alt+F4 or Alt+Space from Windows when an app binds it (`minds:run-chord`). Until a workspace reports, Cmd+W / Ctrl+W keeps closing its focused window, as an older workspace expects. While the keyboard shortcuts page in Workspace settings records a shortcut, main runs none and hands the recorder the keys the OS would act on (`minds:record-chord`); the page is told whether it runs in the desktop app (`minds:embedder-capabilities`).
