The smoke journey runs default-workspace-template's OOM drill in its Imbue Cloud workspace as step 3c, right after the template's CI suites (step 3b) and under the same `MINDS_SMOKE_SKIP_DWT_TESTS` switch, so it runs in every desktop release's staging rehearsal. The drill sheds a memory-holding sleeper at each score the template's shed policy assigns under the workspace's real earlyoom, in a gVisor container on a pool host, and checks each kill against a prediction. Its result is reported as one more template test (`dwt:oom-drill::system/services/oom_priority/bin/oom_drill.py`): a failed drill fails its own subtest with the order the sleepers were shed in and the pick it called wrong, skips the rerun like any failed template test, and writes `oom-drill/summary.md` for the CI job's page. The journey's timeout and a session's `PYTEST_MAX_DURATION_SECONDS` (10200) grow to fit the step's ten minutes. The release runbook, the services runbook and the testing overview say what the drill checks and how to read its result.
