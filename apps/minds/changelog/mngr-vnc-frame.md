- The embed contract is at version 9: `minds:immersive-request` (workspace to chrome, `{ windowId, on }`) and `minds:immersive-changed` (chrome to workspace, `{ on, keyboardLocked, error? }`), plus the optional `immersive: true` field on `minds:embedder-capabilities`. A workspace Screen window can ask the Imbue Studio chrome for immersive mode: the workspace frame goes Fullscreen-API fullscreen with the keyboard locked, so every key (Ctrl+W, Ctrl+N, F11, Escape included) reaches the remote desktop; holding Escape leaves. The chrome announces the capability, ends the mode whenever fullscreen ends by any route, and reports every transition. The frame's sandbox list gains `allow-pointer-lock`.

- The desktop app silences its application-menu accelerators and its `before-input-event` key relays (`escape-pressed`, `close-active-tab`) while a window's frame is immersive, and installs a default-session permission handler: Electron's grant-everything default stays, written down, and `fullscreen`, `keyboardLock` and `pointerLock` are granted only to a page whose top-level origin is the chrome's own, so no Chrome lock prompt appears inside the app.

- Two agent-reachable routes for the workspace Screen's service, through the latchkey `minds-api-proxy`: `GET /api/v1/agents/<agent_id>/media-endpoints` answers where the workspace host's published ports are reachable from this desktop (read from the host record discovery keeps current; empty for a host with none), and `GET /api/v1/agents/<agent_id>/ice-servers` answers TURN relay servers minted from the connector for the signed-in account that owns the workspace, cached per account and refreshed at half life, or an empty list with status 200 when no account is signed in or the connector refuses. The discovery consumer and `mngr list` parser now carry `host.published_endpoints`.

- Tier bring-up (`docs/deploy/setup/tier-bringup.md`, `vault.md`) covers the Cloudflare Realtime TURN key the connector mints the Screen's relay credentials from (`secrets/minds/<tier>/turn`: the key id and the key API token; the usage sweep queries analytics with the tier's existing `CLOUDFLARE_API_TOKEN`, which also needs `Realtime: Edit` to create the key through the API) and the Cloudflare billing notification on the key's monthly spend; `docs/deploy/ops/turn-kill-switch.md` is the runbook for rotating the key, which invalidates every outstanding credential at once, and for the narrower per-account measures.

- Every tier's `deploy.toml` gains `max_turn_relay_gb_per_month` on every plan (20 / 50 / 200 GB for free / explorer / ally, 0 for guest) and the `turn` secret in `[secrets] services`, which `minds-admin env deploy` pushes from `secrets/minds/<tier>/turn`; the entry must exist (empty values allowed) before a tier's next deploy.

- `docs/deploy/setup/host-pool-setup.md` explains that a pool host publishes exactly the ports the bake's create templates declare, that pool hosts baked before published ports existed never match a lease that declares them, and that the pool must be rebaked at a template tag that starts declaring ports before that tag is promoted.

- `test_mngr_settings.py::test_a_refused_session_refresh_reaches_the_sync_pass_through_a_real_observe_stream` is marked flaky: CI once saw its stub connector reset the refresh connection instead of answering `200 {"status": "ERROR"}`. The stub now drains the refresh request body before answering, so closing the socket no longer turns into a TCP reset; the mark stays until CI confirms the fix.
