The error-reporting screen, shown once after the first-run start flow, is now a real choice instead of a notice. Titled "Help improve Imbue Studio", it asks "Is it ok if we report anonymized data to help improve Studio?" with a checkbox that starts checked, and its button reads Continue. Continuing as it is keeps error reporting on. Unchecking the box first turns error reporting off, which Settings → Error reporting then shows. Before, the screen only said reporting was on, and turning it off meant finding the setting. `POST /ui/api/onboarding/consent` now takes the answer as `report_unexpected_errors`; a request without it still just marks the screen answered.

A new install is now asked during onboarding. The start flow's "How do you want to run it?" question carries the same pre-checked checkbox just above its answers, the last press before the first workspace is created. Choosing Imbue Cloud, Custom setup, or "I already have a workspace (log in)" saves the answer, so a new user is never sent through their first session without being asked. The one-time screen stays for installs that finished onboarding before this change and never answered.
