This is the primary flow for how a user would create a workspace for the first time:

1. User starts the desktop client. The loading screen plays the intro on the install's first launch (the lockup, two typed lines, the lockup parking in the titlebar) while the backend comes up.
2. Once the backend is ready and the install has never been taken past onboarding, the app lands on the start flow: a chat that opens with "Studio is a new kind of personal computer, built on honest software.", answers the "Wait.. what is honest software?" that invites, and closes by asking whether errors may be reported, with "See more" over what that collects and how long it is kept. Answering it either way saves the error-reporting setting and starts the questions.
3. The chat asks where the first workspace should run, recommending Imbue Cloud with a single "Use Imbue Cloud" button; "Run it on this computer" and "Use your own cloud" are small links under it, and "I have an account (log in)" is there for a returning user, who signs in and lands on their workspace list.
4. Imbue Cloud asks for an Imbue account (sign-up or sign-in in the system browser; with one already signed in, it offers to continue with it or use a different one), then creates the workspace under that account with the remote preset. Either link opens the full create form (name, compute, backups, region, repository, branch) as a modal, on the matching card.
5. Submitting a create lands on the creation page, in the normal app frame: the settings the user chose as their own message (folded behind a "Details" chevron), the agent's line on what a workspace is, and, while the workspace is built, the agent's questions: whether the user knows what to build ("I'm not sure", "No", "Yes"), and for one who does not, whether to see examples or describe a problem. The loading box, with the progress bar, the stage caption with the remaining time under it, and the expandable log, stays hidden until the answer; a workspace still being built then gets "Great, let me just finish setting up your workspace..." and the box under it. (A create from the home page's form asks nothing unless its advanced "Use onboarding questions?" switch is on, and shows the box at once.) The desktop client clones the repository (if a URL) and runs `mngr create system-services@<host> --new-host --no-connect --label workspace_display_name=<name> --label is_primary=true --template main --template <mode>` (the agent id is read back from the `created` JSONL event rather than pre-generated).
6. When creation completes and the questions are answered, "You're all set." appears (under the loading box, or straight after the answer when the workspace was ready first), the conversation so far, questions and answers included, is handed to the workspace as its first chat (closing on the welcome written for the answer: an invitation to say what to build, or to describe what is annoying, overwhelming, or tedious, shown on the creation page, for a user who asked to see examples, after a short recording of a to-do list app others have built), and the workspace's color washes over the window, revealing the workspace's own interface open on that chat, which fills most of the desktop. Signing in to a provider there starts the workspace's first agent at once; the user's first message goes to it, and the moment the agent goes to work on it the workspace's own tour starts beside the agent's avatar (and pauses when the agent answers, to resume on the next task).

For subsequent launches:
- The loading screen opens on the parked mark and status line; no intro plays.
- If the user has workspaces (or has completed onboarding), they land on the home page listing every workspace, or on their restored windows.

Creating additional workspaces:
- Users press Create on the home page, fill in the form, and land on the same creation page without the preceding conversation.
- Programmatic creation is available via `POST /api/v1/workspaces`, polling `GET /api/v1/workspaces/operations/create/{operation_id}` for progress.

The point of this whole flow is to make it as easy as possible for users to get a workspace running.
